# 開発spec: 課題作成のゲーム選択UI改良（A3）

**バージョン:** v1.0（2026-07-25）
**実装担当:** Claude Code（Cursor）
**対象リポジトリ:** winniek75/MoWISE のみ（ゲーム側は触らない）

---

## 1. 目的

先生が課題を出すとき、ゲーム名だけでは中身が分からず選べない。説明・サンプル画面・お試しプレイで「見て選べる」状態にする。

## 2. スコープ

### やる
1. **課題作成モーダルのゲーム選択を「カード形式」に変更**
   - 各カード: サムネイル画像 / 日本語タイトル / 説明文（`game_catalog.description_ja`・2行で省略）/ カテゴリバッジ（grammar=緑, phonics=青, eiken=橙, writing=紫, mixed=灰 など）
   - サムネ未登録のゲームはカテゴリ色の背景＋アイコンでフォールバック表示（画像が揃うまで壊れない）
2. **「お試しプレイ」ボタン**をカードに追加
   - `game_catalog.url` を新規タブで開く（先生アカウントのスコア送信はしない＝iframeブリッジを通さない素のURLで開くだけ）
3. **サムネイル基盤**
   - Supabase Storage にバケット `game-thumbnails`（public read）を作成
   - `game_catalog.thumbnail` にStorageの公開URLを登録
   - 画像仕様: 16:9・幅640px・WebP・1枚100KB以下

### やらない（今回の範囲外）
- 生徒側のゲーム一覧画面の変更（別spec）
- ゲーム側リポジトリの変更
- 難易度・学年別のフィルタ機能（将来）
- スクリーンショット18枚の撮影自体（下記「素材タスク」として実装と分離）

## 3. 受け入れ条件

- [ ] 課題作成モーダルで全ゲームがカード表示され、説明文とカテゴリが読める
- [ ] サムネ登録済みゲームは画像が表示され、未登録はフォールバックが表示される（レイアウト崩れなし）
- [ ] 「お試しプレイ」で該当ゲームが新規タブで開く
- [ ] モバイル幅（375px）でカードが1列で崩れず表示される
- [ ] 既存の課題作成フロー（タイトル・期限入力→保存）は変更なしで動作する

## 4. 技術メモ

- ゲーム選択UIは `src/views/teacher/TeacherClassView.vue` 内の課題作成モーダル
- カタログ取得は `src/stores/game.ts`（`game_catalog` を既にselectしている）— `description_ja`, `thumbnail`, `category` を表示に使うだけ。**DBスキーマ変更なし**
- Storageバケット作成はSupabase migrationではなくダッシュボード or MCPで1回だけ実施
- **素材タスク（実装と分離・並行可）:** 各ゲームのプレイ画面スクショ18枚
  - 近道: Remotion `GamesShowcase` 用に抽出済みの実ゲームプレイ素材からフレーム切り出しできる可能性あり（要確認）
  - 撮れ次第 `game-thumbnails` にアップし、`UPDATE game_catalog SET thumbnail = '...' WHERE id = '...'` で順次反映（フォールバックがあるので部分反映でOK）
